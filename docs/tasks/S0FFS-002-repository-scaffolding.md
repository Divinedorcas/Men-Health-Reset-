# Task Specification: S0FFS-002 — Repository Scaffolding & Developer Experience

**Task ID:** S0FFS-002  
**Sprint:** Sprint 01  
**Status:** In Progress / Ready  
**Decision Reference:** [ADR-001: Technology Stack Decision](../decisions/001-stack-decision.md)  

---

## 1. Context

The repository today is a single README. An engineer joining the project has no code to run, no tests to trust, and no signal about whether their machine is even set up correctly. This task is the concrete answer to *"can I build here?"* — until it ships, every other sprint task (auth, dashboard, deploy) has nowhere to land. The sprint brief calls for a repo a new engineer can clone and run in under fifteen minutes, with tests that pass and a CI that proves it on every push. That is the floor, and that is what this ticket delivers.

---

## 2. Outcome

A new engineer — fresh machine, no prior context — clones the repository and follows the README. Within fifteen minutes, the app is running locally, every test in the suite passes, and they have confidence the environment is correctly configured. Every subsequent push to any branch triggers automated checks that run the same suite and report a clear pass/fail signal before a PR is merged. The team no longer wonders "does it work on someone else's machine?" because CI answers that question on every commit.

---

## 3. Acceptance Criteria

All 7 acceptance criteria must be satisfied for the task to be marked complete:

| # | Criterion | Verification Method |
|---|---|---|
| **01** | A teammate who has never cloned the repo can follow the README from a blank machine and have the app running locally and all tests passing within fifteen minutes — measured by having them do it without verbal help. | Timed clean setup following README step-by-step. |
| **02** | A single command runs the full test suite locally and exits with a clear pass/fail summary (not raw output requiring interpretation). | Run `scripts/verify.ps1` or `scripts/verify.sh` locally. |
| **03** | Every push to every branch triggers automated CI that runs the same test suite and reports the result visibly on the pull request or commit before merge is possible. | `.github/workflows/ci.yml` matrix on push/pull_request. |
| **04** | A failing test in CI produces enough context (test name, failure message, line reference) that the author can reproduce the failure locally without guessing. | Verbose `--testdox` output on test failures in CI logs. |
| **05** | The project manifest declares all dependencies explicitly, so a clean install on a fresh environment succeeds without missing-library errors. | `composer.json` / `composer.lock` and `package.json` / `package-lock.json` explicit locking. |
| **06** | Linting runs as part of the same test suite and a lint violation fails the build with a message pointing to the offending file and rule. | Laravel Pint (`./vendor/bin/pint --test`) and ESLint (`npm run lint`). |
| **07** | The README includes a step that confirms the environment is healthy (e.g., a smoke-test command the engineer runs after setup) so they know the clone succeeded before they write any code. | `GET /api/health` returning `{"status":"ok","service":"men-health-reset-api"}`. |

## 5. Scope & Constraints

- **Technology Stack**:
  - Backend: Laravel (PHP 8.2+)
  - Frontend: React + Vite (Node.js 20 LTS)
  - Testing: PHPUnit / Pest for backend, Vitest / Testing Library for frontend
  - Linting: Laravel Pint (PHP), ESLint (JavaScript / JSX)
- **Strict Out-of-Scope Items for S0FFS-002**:
  - Do NOT implement user authentication, login screens, or session logic (handled in S0FFS-003).
  - Do NOT implement health dashboards, metrics, or personal space UI.
  - Do NOT introduce Docker, Kubernetes, microservices, Redis, or Next.js.
  - Follow ADR-001 strictly.

---

## 6. Definition of Done

1. [x] Directory structure matches target layout.

3. [x] `backend/tests/Feature/HealthTest.php` asserts health check response.
4. [x] Single verification script runs all tests + linting and reports clear PASS/FAIL summary.
5. [x] `.github/workflows/ci.yml` runs full backend and frontend checks on all branches.
6. [x] `README.md` enables a new engineer to clone and verify healthy setup in < 15 minutes.
